### 매칭 기준

- 저장된 원문은 유지하고 매칭용 공백만 정규화했다.
- 번역은 미끼 사전 안에서 세부 종류·제조사에 맞는 항목을 선택한다. 밑밥 사전 조회나 미끼/밑밥 전환 기능은 만들지 않는다.
- `bait_matches.csv`는 catches의 바늘 미끼 위치에 대한 연결표다. 원본 catches가 이름만 제공해 종류·제조사를 확정할 수 없는 26개는 각 후보의 entry_id·context·tab·type·maker를 전부 남기고 단일 번역 칸을 비웠다. 번역 문자열이 같아도 항목을 합치거나 첫 후보를 선택하지 않는다. 종류를 알 수 있는 화면에서는 그 화면의 종류에 해당하는 항목을 사용하면 된다.
- 한국어 성분에 대해서만 끝의 숫자 또는 `7/4/3` 형태를 크기 후보로 분리했다. 번역의 본체는 `*_base`, 원문의 크기 부분은 `size_suffix`에 보관한다. 루어 색상 코드를 제거하는 범용 규칙으로 사용하면 안 된다.
- catches는 바늘 미끼이므로 밑밥 탭과 딥을 후보 및 적용용 사전에서 제외했다.
- 예: 통보리는 천연미끼의 `Pearl barley / Каша перловая / 大麦粥`만 사용한다.
- 기존 build_dict.py가 기록한 수정에 따라 팝업 보일리의 `신선한 라임`은 `신선한 라임 팝업`으로 후보 키를 구분했다. 기존 파일은 수정하지 않았다.
- 별칭 후보: `게와 생선 펠릿` → `게와 생선 펠릿 펠릿`, `민물 크릴 펠릿` → `민물 크릴새우 펠릿`, `붉은 크릴 펠릿` → `붉은 크릴새우 펠릿`, `민물 크릴` → `민물 크릴새우`. 오타·축약 추정에 의한 대응이며 게임 실표기 최종 확인 대상이다.
- 단일 후보도 자동 확정 번역은 아니다. 기존 build_dict.py의 다른 오류 수정·별칭은 이번 원본 기반 후보표에 일괄 반영하지 않았다. 적용 전에 기존 수정 내역과 대조해야 한다.

### 남은 항목

- 종류·제조사 확인 필요 예: 뉴트럴, 스파이스, 새우, 바닐라, 바나나. 미끼/밑밥 구분은 이미 반영했다. 남은 것은 이름만 있는 catches를 종류·제조사별 항목 중 어디에 연결할지의 문제이며 사전 항목 자체는 각각 완성된 번역을 유지한다.
- 미매칭 예: 스피너베이트, 발포 고무 모형 물고기, 잰더용, 크랜베리 팝업, 코코넛과 크림 화이트. 루어는 이 미끼·밑밥 표의 범위 밖인 항목이 있어 장비 자료로 보완해야 한다.
- 미확정 항목은 서비스 적용 시 원문으로 표시하는 것이 안전하다. 크기·색상·조합 성분을 누락하지 않아야 한다.

## 메뉴·상태 문구

- `menu_terms.csv`: 밑밥 메뉴를 제외하고 3개 참조 메뉴 용어와 서비스용 번역 초안을 구분했다.
- 참조의 `鱼种档案`, `地图图鉴`은 각각 어종 자료·지도 도감이라는 메뉴 의미다. 카드의 짧은 항목명에는 문맥에 맞춘 번역이 필요하다.
- 즐겨찾기·어종 관리·활성도 4단계는 우리 서비스 문맥에 맞춘 초안이다. 참조 사이트에서 그대로 검증된 문구로 취급하지 않는다.
- 특히 `탐색`은 비활성과 활성 사이의 판단 단계이므로 검색 기능이나 활성 확정으로 오역하면 안 된다.

## 검증과 적용 범위

- 수역 CSV의 18개 기본명과 별칭 2개로 DB의 distinct waterbody 20개가 모두 매칭되는 것을 확인했다.
- 미끼 후보표의 분류 합계는 1,072개이며, 원본 CSV의 네 언어 빈 값은 0개다.
- 수정 검증: 미끼 사전 381행의 entry_id 중복 없음, 밑밥·딥 제외, 매칭표 1,072행의 모든 후보 및 단일 entry_id가 사전에 존재함을 확인했다. 유지한 항목의 번역·종류·제조사는 변경하지 않았고 복수 항목도 임의로 선택하지 않았다.
- 서비스 반영: `rf4site/translations/species.csv`는 어종 251종, `waterbodies.csv`는 수역 18곳과 별칭 2개, `baits.csv`는 단일 항목으로 연결할 수 있는 미끼 표시 키 512개(원본 개체 351개)를 포함한다. 미끼 기본명과 크기 포함 관측명을 같은 원본 entry_id에 연결했고, 서로 다른 개체를 이름만으로 합치지 않았다.
- 밑밥·딥과 다의적인 미끼 후보는 서비스 사전에 넣지 않는다. 확인되지 않은 미끼·루어 명칭은 원문을 표시한다. 크기·색상·조합을 유지하는 표시 함수와 실제 화면 연결은 D-57에서 검증한다.
